# Native Git layout

## Canonical project shape

A common single-service repository layout is:

```text
repo/
├── .postman/
│   └── resources.yaml
├── postman/
│   ├── collections/
│   │   └── My API/
│   │       ├── .resources/
│   │       │   └── definition.yaml
│   │       ├── Users/
│   │       │   ├── .resources/
│   │       │   │   └── definition.yaml
│   │       │   ├── Get User.request.yaml
│   │       │   └── Get User.resources/
│   │       │       ├── examples/
│   │       │       └── scripts/
│   │       └── Health.request.yaml
│   └── environments/
└── src/
```

The exact metadata placement and optional directories should follow files generated by the local Postman version. Never reorganize a working collection merely to match an example.

## Source-of-truth hierarchy

When editing an existing repo:

1. Repository code/spec defines what the API actually does.
2. Existing Native Git files define formatting conventions.
3. Postman CLI lint defines current schema acceptance.
4. This skill provides fallback patterns.

## File rules

- Requests are authored as `*.request.yaml`.
- Prefer `.yaml` for new output even if parsers may accept `.yml`.
- Request-specific resources use a sibling `<request-name>.resources/` directory.
- Metadata is stored in `definition.yaml` under the repository's established reserved-resource layout.
- Use forward slashes in paths stored inside Postman metadata/manifests.
- Treat names as case-insensitively unique where Postman does.

## Ordering

Postman Schema 3 uses numeric ordering values. Existing repositories may have large or fractional values. Do not renumber the whole collection.

When adding one request:

- inspect neighboring `order:` values;
- choose a value that places the request correctly without touching unrelated requests;
- if no ordering convention exists, use a simple value such as `1000`, then increment by `1000` for a new isolated folder.

## Local View vs Cloud View

Treat Local View/Git files as the editable development state. Cloud synchronization is a separate operation. Do not assume editing cloud state updates the repository.
