# HTTP request patterns

## Required core

A normal HTTP request needs these semantic fields:

- `$kind: http-request`
- `name`
- `url`
- `method`

`order` is strongly recommended when neighboring files use it.

Supported HTTP method spelling for ordinary requests:

`GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS`

## URL and variables

Prefer variables:

```yaml
url: "{{base_url}}/users/{{user_id}}"
```

Avoid committing environment-specific hosts:

```yaml
# Avoid as a default in shared Git files
url: "https://prod.example.internal/users/123"
```

## Query parameters

For maximum compatibility, inspect existing files generated by the installed Postman version. Some Native Git builds have had linter issues around generated `queryParams` shapes.

Safe decision order:

1. copy a sibling request that already has query parameters;
2. if no sibling exists, encode a simple query in the URL temporarily and lint;
3. prefer the representation accepted by the local Postman CLI/app;
4. do not mass-convert other requests merely for stylistic consistency.

## Headers

Reuse the collection's existing header shape. Common repositories may use a map-like or list-like representation. Do not mix styles inside one folder unless Postman generated it.

Never hardcode credential headers.

## Request bodies

Copy body syntax from a sibling using the same content type. Keep JSON content valid JSON even when embedded as YAML block text.

For a JSON endpoint, preserve `Content-Type: application/json` only when the surrounding collection requires explicit headers; Postman may derive it from body type.

## Authentication

Prefer inherited collection/folder auth. Request-level auth is for exceptions.

Do not duplicate bearer/API key credentials into each request. Use variables such as `{{access_token}}` or whatever the repository already uses.

## Naming

Use task-focused request names that match local conventions, for example:

- `Get User`
- `List Users`
- `Create User`
- `Update User`
- `Delete User`

If the repository prefixes sequence numbers or status expectations, preserve that convention.
